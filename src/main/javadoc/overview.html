DDD Utils ({@code com.schoste.ddd:utils}): helper classes for the DDD libraries dao and domain-repository, and for projects that use them. Java 8 or later, no runtime dependencies. The full guide with more examples is the README of the source repository, github.com/phisch84/dao-domain-utils; it also ships in the jar as {@code META-INF/README.md}, next to {@code CHANGELOG.md} and {@code LICENSE}.

Where to start

Declare variables with the interface (it has the usage rules in its documentation) and create the implementation:

Types and what to instantiate
InterfaceCreate withWhat it does
{@link com.schoste.ddd.util.CachedObject}{@link com.schoste.ddd.util.fs.CachedObjectImpl} Holds one {@code Serializable} object, keeps it in memory only weakly and reloads it from a cache file on demand.
{@link com.schoste.ddd.util.CachedHashMap}{@link com.schoste.ddd.util.fs.CachedHashMapImpl} A {@code java.util.Map} whose values are each kept in a {@code CachedObject}, so large maps don't fill the heap.
{@link com.schoste.ddd.util.NestedMap}{@link com.schoste.ddd.util.NestedHashMap} A map with key paths (a trie): {@code put(k1, k2, k3, value)}, {@code get(k1, k2, k3)}, {@code getSubMap(k1)}.
{@link com.schoste.ddd.util.CachedNestedMap}{@link com.schoste.ddd.util.fs.CachedNestedHashMapImpl} A {@code NestedMap} whose values are cached like in a {@code CachedHashMap}.
{@link com.schoste.ddd.util.CachedQueue}{@link com.schoste.ddd.util.fs.CachedQueueImpl} A thread-safe FIFO {@code java.util.Queue} whose elements are each kept in a {@code CachedObject}.
(a class){@link com.schoste.ddd.util.RunningStatistics} Thread-safe count, sum, min, max, mean, variance and standard deviation, one data point at a time.

The {@code Abstract*} classes are for writing an implementation for another storage. The test jar (classifier {@code tests}) contains the contract tests every implementation must pass.

Rules for all cached types

  • Save changes while you hold a reference: {@code put}/{@code offer} save a value; save a changed value with {@code commit()} (or {@code put} again). Changes that weren't saved are lost once the value is garbage collected.
  • Values may be copies: once a value was garbage collected, {@code get} returns a copy loaded from the storage.
  • Close when done: {@code close()} deletes the cache files (use try-with-resources); files that weren't closed are deleted when the JVM exits. Removing or replacing a value deletes its cache file.
  • Values must be {@code Serializable}, null values are rejected, and a cached object's hash code must not change.
  • Serializing a cached type writes only references to its cache files, not the values: commit first; the copy shares the files with the original.
  • Threads: {@code CachedObject}, {@code CachedQueue} and {@code RunningStatistics} are thread-safe; the maps are not (like {@code java.util.HashMap}).
  • Storage errors in methods of {@code java.util} interfaces are thrown as {@code IllegalStateException} with the original exception as cause.

Example

try (CachedHashMap<String, ArrayList<String>> map = new CachedHashMapImpl<>("/var/cache/my-app"))
{
    map.put("a", new ArrayList<>(Arrays.asList("1")));   // put() saves the value

    ArrayList<String> a = map.get("a");                  // may be a copy loaded from the cache file

    a.add("2");
    map.commit();                                       // saves all values which are in memory
}                                                       // close() deletes all cache files

NestedMap<String, Integer> population = new NestedHashMap<>();

population.put("europe", "austria", "vienna", 2_000_000);
population.get("europe", "austria", "vienna");          // 2000000
population.getSubMap("europe").size();                  // 1: values at any depth

RunningStatistics stats = new RunningStatistics();

stats.accept(2.0);
stats.accept(4.0);
stats.getMean();                                        // 3.0
stats.getSampleStandardDeviation();                     // 1.414...
